# Sector ID and storage compatibility

`SectorId` is an opaque, rule-local `usize`, not a physical label or a
cross-version wire format. Persist semantic labels such as `(charge, parity)`
instead. Equal numeric IDs from different rules need not mean the same sector.

## Product-sector codecs

`ProductFusionRule` defaults to `TensorKitProductCodec` (Cantor pairing).
`PackedProductCodec` is an explicit fixed-width alternative. Codec choice
changes `RuleIdentity`: spaces and plans from the two codecs cannot mix even
when their decoded labels agree.

Changing a codec preserves fusion, duality, coefficients, degeneracies and
results matched by semantic tree labels. It can change numeric IDs, sector
iteration, block order, raw buffers and the tensor generated by a fixed seed.
`GradedSpace::sectors()` returns internal ID order; callers needing another
order must use semantic labels or an explicit ordering.

`rand_with_seed` fills storage order. Reproducibility is limited to a fixed
version and layout. For a fixture independent of codec/layout, use
`from_subblock_fn` with provider-labelled fusion trees and local indices.

## Sector order where TensorKit's order is observable

Storage uses ID order. Two operations instead need a semantic basis order:

- At an exact cross-sector truncation tie, `find_truncated` uses the provider's
  `sector_order_key`. Rank selection keeps the earlier sector first; error
  selection discards it first. Per-sector space/tolerance decisions have no
  cross-sector tie.
- `isomorphism` and `isometry` between different spaces pair or select leading
  trees in TensorKit basis order, including dual flags and inner lines.
  Product inner lines follow fusion-symbols' native factor channel order,
  varying the first factor fastest; this differs from sorting product sectors
  by their comparison key. A generated Lie factor inside a product retains
  category channel order, while standalone `LieGroupFusionRule` sorts encoded ids.
  For SU(N) with three or
  more legs on a side, TensorKit's dictionary-based inner-line order has no
  stable counterpart; symtn uses sector order there.

| Rule | Semantic comparison order |
| --- | --- |
| U(1) | `0, +1, -1, +2, -2, …`; storage IDs instead begin `0, -1, +1, …` |
| Z2, Z_N, fermion parity | Ascending label |
| SU(2) | Ascending twice-spin |
| CU(1) | Charge magnitude, with `0+` before `0-` |
| TableRule | AnyonWiki object order; Ising is `1, ψ, σ`, unlike TensorKit |
| Products | Total enumeration degree, then lexicographic over flattened factors |
| `LieGroupFusionRule` | Dynkin-label sum, then lexicographic; quotient exclusions leave holes |

A provider without a TensorKit counterpart defaults to ID order. A codec whose
IDs disagree with its intended semantic order must override `sector_order_key`.
Implementation and reference pointers are in
[`truncation.rs`](../symtn-matrixalgebra/src/truncation.rs),
[`product_rule.rs`](../symtn-sectors/src/product_rule.rs) and the
[basis-order tests](../symtn-core/src/tests/fusion_space/tensorkit_tree_order.rs).

The Lie-group codec uses the root-system rank, preserves quotient holes and
rejects excluded labels on encode and decode. Rank-one labels are bounded by
`u32::MAX`; higher-rank labels share the target `usize` ID budget. Full
root/global-form metadata and the actual category fingerprint enter identity,
so equal labels or fingerprints across different groups are insufficient for
compatibility.

## Caches

Rule identities include codecs. The process-global structure caches therefore
cannot reuse one codec's layouts or transforms for another; see
[layering](layering.md#inside-symtn). symtn persists no tree-transform plans.
Application caches keyed by raw IDs must be rebuilt from semantic labels.

`symtn-network::{save_plan_cache, load_plan_cache}` is separate: explicit
persistence stores topology-derived optimizer output, not lowered tree
transforms.

## Target width

Packed `U(1) × fZ2` and `fZ2 × U(1) × SU(2)` reserve 33 and 41 bits
respectively. They require a 64-bit target, as does the complete encoded U(1)
label set. Checked constructors return a width error on narrower targets.

U(1) charges range from `i32::MIN + 1` through `i32::MAX`.
`U1Irrep::try_new(i32::MIN)` returns `None`; `new(i32::MIN)` panics because
that charge has no representable dual. A fusion sum outside the range returns
`FusionAlgebraError::U1FusionOverflow`, with no wrapping or saturation.
